# 待优化点与权限边界

这份文档汇总 hermetic-dmsa 截至 `0.2.0.dev0` 的全部待优化点、明确的能力边界与权限/鉴权事实。它只对当前代码和文档负责，不把"计划做"写成"已具备"，也不把合成自测写成官方成绩。所有判断都能回到代码位置或既有文档。

最后更新：2026-11-25 · 分支 `main`（由 `feat/coding-memory-rsi` 合并）

---

## 一、先说清楚它是什么

DMSA = **D**ifferentiated **M**emory **S**elf-evolving **A**gent，`hermetic` 指自包含、可离线。原始设计是"记忆可微"四件套（PMD 溯源梯度 → SGA 语义梯度聚合 → ToolBP 工具反向传播 → MCP 接入）。

但产品重心已经从"可微记忆 + 多 agent 共识"移到**编码记忆检索层 + 离线 RSI**。这是理解所有待优化点的前提：名字里的"Self-evolving"目前是叙事，不是完整能力；真正跑通的是内层 RSI 和检索侧的证据纪律。

它的差异化来自**任务收缩**——把"通用 agent 记忆"缩到"仓库内工程证据"——不是技术领先。把同一套东西搬到用户偏好记忆，没有标识符、没有测试可验、outcome 无从判定，立刻失效。

## 三、检索与排序质量

### 3.1 缺陷修复 51.52%：缺根因因果链

新功能 70.59%、缺陷修复 51.52%，20 点落差是这个系统的边界投影。"找相似功能"吃词面红利（标识符是强信号），"找根因"需要真正的因果链。

代码里有多跳骨架（`MAX_HOPS=3`），但扩展词只来自已命中证据的路径与符号，深度不够。要补的是"测试失败 → 栈帧 → 修改点 → 引入版本"这条链，而不是再加一路词面匹配。这一步无论如何绕不开对代码结构的理解（见 3.2）。

### 3.2 代码结构理解很浅

`code_anchors` 只有 `modifies / mentions / defines / test / frame` 五类正则，全部来自轨迹原文里的显式标记，不做语义推断。没有调用图、没有数据流、没有跨文件依赖。

对比 HippoRAG 的 PPR 图传播，这是另一个量级。`code_relations` 虽然把锚点转成了工程关系边（`defines_symbol / validates_test / touches_file`），但表达力受限于锚点本身。

### 3.3 `relation_window` 默认 0

`SearchPolicy.relation_window` 默认 `0`（范围 `[0, 20]`），意味着"改了同一文件 / 定义了同一符号 / 被同一测试覆盖的历史切片"这种关系扩展，**默认配置下根本不生效**。文档里把它当卖点写，但默认值让它在开箱使用时缺席。

要么给一个有实测支撑的默认值，要么在文档每个提到它的地方明确标注"需手动开启"。

### 3.4 稠密通道不是 ANN 级

默认是 scope 内有界精确扫描（≤10,000 切片），Qdrant ANN 是可选路径。10,000 片之后行为没有验证过，1.8B token 规模未压测。这决定了它目前只能算单机/小团队工具——这一点 README 已诚实写明。

### 3.5 交付预算与平台契约冲突（已缓解，但需持续盯着）

平台写死 `top_k=100`。曾把交付压到 12 条做"紧凑包"，真实快照上交付量掉到请求量的 12%，风格类证据全丢。现已改回与 `top_k` 同量级，用 `score_floor_ratio` / `min_evidence` / `per_session_limit` / `per_path_limit` + 字符与 token 双预算控制，不靠砍总数。这是已解决的历史问题，但任何新的"省 token"改动都要重查这条。

## 四、自进化：名字与能力的差距

### 4.1 只有内层 RSI 是真跑通的

外层 loop 只是"比较两个提案器（确定性 vs 模型辅助）"，默认不自动激活。对比 langmem 有真 `GradientPromptOptimizer`，evolver 有 4,590 次对照实验（9.1% → 18.57%）。在这条轴上这是最弱的一档，**对外不该把"自我进化"当第一句**。

### 4.2 门禁只认 recall/NDCG，lineage 被按设计拒绝

实测配对回放（`benchmarks/coding/lineage_replay.py`，合成语料，非官方成绩）：

| 指标 | 默认（`lineage_window=0`） | lineage（`=1`） |
|---|---:|---:|
| 平均 recall | 1.00 | 1.00 |
| 平均 NDCG | 1.00 | 1.00 |
| 取代信息送达率 | 0.00 | 1.00 |
| `offline-rsi-gate-v2` | — | **拒绝** |

固定门禁要求至少一例严格改善 recall/NDCG。lineage 不制造新的相关命中，只是在已有候选上标注"这条已被取代"，所以两臂检索质量相同，门禁按设计拒绝。

**结论：lineage 是透明度通道，不是排序优化通道。** 应由调用方按场景显式打开（例如需要审计"结论是否已被推翻"的调试会话）。若将来要让它自动晋升，必须先扩展门禁维度（把"取代信息送达率"纳入接受条件）并重标定——这是待优化点 #7。

### 4.3 SGA 与 ToolBP 的接入判断（设计取舍）

| 组件 | 判断 | 理由 |
|---|---|---|
| SGA 语义梯度聚合 | 只进离线提案器 | 在线接入会把"零依赖 + 确定性"变成"依赖 embedding 服务 + 聚类不稳定"，破坏 `offline-rsi.md` 整条论证。最多作为 `ModelAssistedPolicyProposer` 旁边的可选臂。 |
| ToolBP 工具反向传播 | 不接 | 它编辑 MCP 工具 JSON Schema 的 AST，与"存代码证据、取代码证据"无自然接口。唯一对应物是"把 `SearchPolicy` 当 Variable 做受控编辑"，但 RSI 已经在做这件事，接进来是换实现。 |

### 4.4 条件化冲突分支（待做，收益最高成本最高）

目标：同条件互斥才冲突，不同条件生成分支。这是原创性最高的一条，但需要语义抽取，会破掉零依赖。目前只适合离线做。

## 五、原创资产闲置

PMD 的双向 DAG（`parents + children + siblings + versioning`）是真正区别于 A-MEM 的东西——A-MEM 的 links 是 LLM 插入时生成、永不重算、无版本。但 README 明说：

> 原有 PMD DAG、SGA 文本梯度与 ToolBP 仍然可用，但尚未与 Coding Memory 引擎自动共享记忆；`memory_lineage` 只记录派生层边，不等于完整 PMD DAG。

本轮新增的 `memory_lineage` 表只登记派生层的两类边：`DERIVED_FROM`（经验卡 → 本次原文切片）和 `SUPERSEDED_BY`（旧卡 → 同会话新卡）。它带来了 supersession 通道，但还不是完整 DAG——没有 `MemoryLayer` 与 `CodingMemory` 的共享记忆，边也不表达调用图、数据流或跨文件依赖。

**造了 DAG，产品里只用了派生层这一小块**，这是最该修的事实错位。修法不是给 30 万 chunk 建节点（成本翻倍），而是让 `[episode]` 卡成为 DAG 节点、条件冲突走 provenance 边。

## 六、评测与验证

- 本地 selftest：15 个合成任务（clamp bug / slugify feature / retry-cap bug），真实 `pytest` 判定，多次 seed 下 `resolved=1.0`。**自己出题自己解，说服力有限。**
- AML 第二期代码赛道：Relevant·新功能 70.59%（并列第 3），综合 56%，缺陷修复 51.52%，Noisy 54%。**单点成绩，不是分布，也不是官方可复现实验。**
- mem0 的 LoCoMo 91.6 / LongMemEval 94.8 是不同任务，**不能直接比较，也不能宣称优越**。
- 新增 `lineage_window` / `verification_weight` 后 AML 数字尚未重跑。因为默认关闭，70.59% 对旧策略仍成立；一旦默认开启或调权，必须重跑配对回放和 held-out，否则不能用。

要把它从"工程组合"抬到"有话可说"，缺的是一条端到端受控实验：固定 commit 沙箱 + baseline/candidate 双臂 + 真实 pytest 判定，而不是继续加合成任务族。

## 七、工程与规模

| 项 | 现状 | 影响 |
|---|---|---|
| 原文永不删 | 302,143 切片，靠 `text_hash` 复用后仅 153,234 条不同正文 | 可追溯，但库会持续增长；向量按 float32 字节存（1024 维 ≈ 4KB），已省一半嵌入调用 |
| 写入不调 LLM | 全部是确定性规则 | 便宜、可复现、无幻觉；但信息量上限就是原文显式写出的东西，隐式经验提炼不了 |
| `scope=user#repo` 硬隔离 | `#` 禁止出现在入参 | 不串味；跨仓库复用必须显式 `consolidate` + `transfer`，泛化后仍含具体路径/符号的规则会被拒迁 |
| Hook 失败策略 | 只记日志、退出码 0 | 永不阻塞开发；代价是可能静默丢一轮 |
| 写入原子可见性 | staged → searchable revision、幂等键、manifest/outbox 恢复 | 保住了单库事务，明确不伪称跨库 ACID；PMD 若拆成独立 DB 会立刻破这条 |
| 稠密模式 | 向配置的 embedding 服务商发送源文本 | `sparse-dev` profile 不外发任何数据；竞争模式有数据外发 |

## 八、权限、鉴权与安全边界

以下来自 `docs/security-and-data.md` 与 `README.zh-CN.md`「状态与边界」。这是**明确声明的边界**，不是待办清单；要在共享环境使用，必须自己补上外部控制。

### 8.1 鉴权事实（最重要）

- **单一 API key 授权整个服务的所有 `user_id`。** `user_id` 是调用方提供的检索分区（`caller-supplied`），**不是经过认证的主体**（`not an authenticated principal`）。
- 项目**不宣称多租户安全边界，也不宣称独立认证**。scope 是数据分区，不是鉴权。
- 直接后果：不要把默认服务暴露给互不相关的租户。要在共享公开环境使用，必须隔离客户端，或在前面加一层带认证的网关。

### 8.2 信任边界与当前控制

| 边界 | 威胁 | 当前控制 | 运营方责任 |
|---|---|---|---|
| HTTP 服务 | 未授权 Add/Search | Bearer service key；畸形请求拒绝 | 用长随机 key、轮换、上游终止 TLS |
| `user_id` scope | 跨 scope 读取 | SQL 与 Qdrant 每次检索按精确 scope 过滤 | 隔离客户端或加认证网关 |
| 历史消息 | 提示注入、过期 API 建议、密钥 | 原始证据带 provenance 标签；经验卡只抽显式文本；不执行 | 把召回内容当不可信数据；Add 前审查保留策略并脱敏 |
| MCP 工具失败 | 异常文本泄露本地路径或源载荷 | 固定失败消息；结构化日志只记异常类型 | 日志留在本地并限制访问；不把异常信息写进 MCP 错误 |
| embedding 服务商 | 源文本披露 / 凭据滥用 | 显式 profile；端点与模型校验；key 来自环境/文件 | 审查服务商条款、数据驻留、端点归属、key 范围 |
| RSI 决策/文本服务商 | 诊断或策略数据泄露；不安全模型输出 | 只发聚合失败标签/计数和有界策略候选；校验候选索引；建议不能激活策略 | 审查条款、端点、key 范围；始终跑本地回放门禁 |
| SQLite / Qdrant 卷 | 被盗、误暴露、删除不净 | 持久卷；Compose 默认不发布 Qdrant 主机端口 | 限制主机访问、加密磁盘/备份、文件级拷贝前停服、设保留/删除策略 |
| 容器 / 依赖 | 传递依赖漏洞或镜像被篡改 | 固定本地 PMD 归档、依赖锁、pip-audit CI、非 root/只读容器 | 审查 CI 与上游通告；安全更新后重建；发布 CI 扫描镜像 |

### 8.3 必须知道的硬限制

- SQLite 与 Qdrant 数据**未做应用层加密**。要保护主机、Docker 卷、swap、备份和 crash dump；合规要求时用加密存储。
- Add API 按原文存储消息，**无法可靠推断或移除** API key、个人数据、专有代码。采集真实工作数据前就要设保留期、按项目分库/分 scope、不摄入无权限处理的数据。
- **召回内容可能含对抗指令。** Coding Agent 必须把召回项当作引用的历史证据，绝不能当系统策略或可执行命令；当前代码、测试与任务指令优先。这条不是免责声明，是设计约束。
- Qdrant 默认在 Compose 网络内，但主机管理员与 Docker 网络 peer 仍是受信方；没有认证 + TLS 的设计就不要发布它的端口。
- RSI 模型辅助只发支持的失败标签/计数与候选检索设置，不发源码或原始记忆；候选必须过本地配对回放门禁，**从不自动晋升**。
- HTTP 服务**没有未认证/admin 删除路由**。删除要通过可信运营流程，分别核对 SQLite 与向量库，备份另行过期。删除命名卷不可逆，除非有备份。

### 8.4 事件响应

1. 限制服务网络，轮换 bearer 与服务商凭据。
2. 保留脱敏日志与镜像/依赖标识；不要把源载荷写进事件单。
3. 按 request ID 定位受影响的 `user_id` scope 与服务商请求。
4. 删除 SQLite 与 Qdrant 中的受影响数据，处理备份保留。
5. 从审查过的 commit/lock 重建，跑 smoke 与 scope 隔离检查，记录残余暴露。

## 九、优先级建议

按"收益 ÷ 成本"排序，只列真正值得先动的：

| 优先级 | 动作 | 理由 |
|---|---|---|
| P0 | 给 `relation_window` 一个有实测支撑的默认值，或全面标注"需手动开启" | 成本极低，当前是文档与行为不一致 |
| P0 | 新增通道后重跑 AML + held-out | 不重跑就没有可信的收益数字，`70.59%` 随时可能被误用 |
| P1 | 缺陷根因专项：从测试失败/栈帧到修改点的因果链 | 直接对准最大的 20 点落差 |
| P1 | 把 `[episode]` 卡接成 PMD DAG 节点 | 让最有原创性的资产真正进入产品 |
| P1 | 扩展门禁维度纳入 visibility，重标定后让 lineage 可自动晋升 | 否则透明度能力永远只能手动开 |
| P2 | 条件化冲突分支（离线） | 新颖度最高但需语义抽取，破零依赖 |
| P2 | 生产规模压测与服务商兼容性验证 | 决定它能不能走出单机/小团队 |

## 十、明确的"不该做"

这些不是待优化点，是已经判断过、不建议再投入的方向：

- **ToolBP 接入 Add/Search** —— 与编码证据存取无自然接口。
- **SGA 在线接入** —— 破坏零依赖与确定性，收益覆盖不了代价。
- **给每个 chunk 建 PMD 节点** —— 30 万切片的存储与写入成本翻倍，原文已在 `chunks` 表里当事实来源。
- **把"自进化"当对外第一卖点** —— 目前只有内层 RSI 真跑通。
- **把合成 selftest 的 `resolved=1.0` 当官方成绩** —— 自己出题自己解。
